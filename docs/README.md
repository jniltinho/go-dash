## What it does

A single-binary web panel that aggregates links into a header **toolbar with
menus and nested submenus**. Each link opens in a **tab of the central area**
(sandboxed iframe, several systems open at once, state preserved between tabs)
or in a **new browser tab**, and can be shown in the menu, as a card on the
**Home** tab, or both. The UI is in English.

| Layer | Stack |
| --- | --- |
| Backend | Go 1.26 · Cobra · viper (TOML + env) · Echo v5 · SQLite (pure Go) · slog |
| Frontend | Vue 3 · TypeScript · Vite+ · DHTMLX Suite 9 (Layout, Toolbar, Tabbar, Tree, Form) · Tailwind CSS v4 |
| Delivery | one static binary with the frontend embedded; Docker image ~50 MB |
| Screens | slim bars (40/32 px) scaling for Full HD, QHD and 4K |

## Themes

25 themes in six groups of the **Theme** menu, each in **Flat** or **No Flat**
(gradients, bevels and soft shadows), never with rounded corners. Each analyst
picks their own (kept in their browser; the active theme and style show in bold); `default_theme` sets the theme for
first visits (default: Ocean Light).

| Group | Themes |
| --- | --- |
| Dark | Blue and Black, Dark, Graphite, Midnight |
| Light | Light |
| Brand | Ocean Light, Ocean Dark, Bio Manager (Criare standard) |
| Inspired | Google, Microsoft, Super Mario Galaxy, Brasil, Winamp |
| Systems | Windows 10, Windows 7, Windows Vista, Windows XP, Windows 98, macOS, Classic Mac OS, Ubuntu, Linux KDE, xterm |
| Special | Matrix, High Contrast |

Every text/background pair of every theme meets **WCAG AAA (≥ 7:1)**, checked
by an automated test. Inspired and system themes only borrow color palettes and
typography styles; no logos or other trademarked assets are used. Screenshots
are generated by `make screenshots` (`frontend/screenshots/themes.spec.ts`)
from a demo instance.

### Adding a theme

Create `frontend/src/theme/registry/<name>.ts` (a `ThemeDefinition`: colors,
gradients, font, group, scheme and optional bevel/glow), register it in
`registry/index.ts`, then run `make test` (the contrast test covers every
registered theme) and add it to `THEME_GROUP` in `frontend/e2e/helpers.ts`,
the e2e loop and `screenshots/themes.spec.ts`.
Component CSS never contains theme-specific rules.

## Menu and cards

Each item has **"Show in"** (`placement`): the header menu, a card on the
"Home" tab, or both (default). The default card order is the menu order set in the admin
tree. Each analyst moves their own cards like Grafana panels: drag a card by
its header, or use the small arrows that show on the header on hover or
keyboard focus; no login and no arrange mode. That order stays only in their
browser (`localStorage`) and never changes anyone else's. Cards added later by
an admin go to the end. Dashboards that are already open pick up admin changes
(new, edited or reordered items) without a reload: when the tab or window
regains focus, and every 30 seconds (an unchanged menu costs a `304`).

## Dashboards

One binary serves several independent dashboards, each with its own **title**
(toolbar and browser tab), menu, cards and optional password:

| Address | Dashboard |
| --- | --- |
| `/` | the **default** dashboard (no slug; its empty title means the configured `title`) |
| `/dash/<slug>` | a named dashboard, e.g. `/dash/acme`, `/dash/globex`, `/dash/initech` |

- Slugs: 1 to 40 lower-case letters, digits or inner hyphens; `admin`, `api`,
  `assets`, `dash`, `default`, `healthz` and `login` are reserved. `/dash/Acme/`
  redirects to `/dash/acme`, `/dash/default` to `/`; an unknown slug shows
  "Dashboard not found".
- **Password (optional, per dashboard, also on the default one):** visitors
  see an unlock screen; the right password opens a viewer session for that
  dashboard only (same 2 h idle / 12 h absolute limits as admin sessions).
  "Lock" in the toolbar ends it. Changing or removing a dashboard password
  logs its viewers out — and only them. A logged-in admin opens every
  dashboard without its password. The password hides the list of links, not
  the linked systems: those keep their own login.
- Unlock attempts share the `login_rate` limit per IP across all dashboards
  (a separate counter from admin login).
- Upgrading an existing database moves every item to the default dashboard;
  nothing changes until a dashboard or password is added. Take a
  `go-dash backup` before upgrading: older binaries cannot read the new schema.

## Admin

`/admin` edits the menu tree (items, submenus, icons, target, placement) and is
enabled when an admin password is configured. **Duplicate** copies the selected
item (not its subitems) into a new form — adjust and **Save**; **Copy**
next to the URL puts it on the clipboard. **Dashboard: …** in the toolbar
picks the dashboard being edited (items, order, import/export apply to it
only) and **Manage dashboards…** creates, renames (title and address),
deletes dashboards and sets or removes their passwords.

## CLI

```text
go-dash serve    [--addr :8080] [--public-url URL] [--title T] [--seed menu.json]
                   [--max-tabs 10] [--frame-src "http: https:"] [--iframe-sandbox TOKENS]
                   [--tls-cert F --tls-key F] [--cookie-secure] [--trust-proxy] [--dev]
go-dash migrate
go-dash dash list [--json]
go-dash dash add SLUG --title T
go-dash dash update SLUG [--slug NEW] [--title T]   # "default" = the dashboard at /
go-dash dash remove SLUG [--force]
go-dash dash set-password SLUG [--stdin]          # 8 to 72 bytes; revokes its viewers
go-dash dash clear-password SLUG
go-dash menu list [--tree] [--json]
go-dash menu add --title T [--url U] [--target iframe|blank] [--placement menu|card|both]
                   [--parent ID] [--icon "mdi mdi-x"]
                   [--description D] [--position N] [--disabled]
go-dash menu update ID [same flags; only the ones given change]
go-dash menu remove ID [--force]
go-dash menu export [-o file.json]
go-dash menu import file.json [--replace]
# every menu subcommand takes --dash SLUG (default: "default", the dashboard at /)
go-dash admin set-password [--stdin]
go-dash backup -o backup.db
go-dash version
```

Global flags: `--config file.toml`, `--db path`, `--log-level`, `--log-format text|json`.

## Configuration

Precedence: **flags > `DASHBOARD_*` environment variables > TOML file > defaults**.
`./dashboard.toml` is read automatically when present; see
[`dashboard.toml.example`](../dashboard.toml.example).

| Key (TOML) | Env | Default | Purpose |
| --- | --- | --- | --- |
| `addr` | `DASHBOARD_ADDR` | `:8080` | listen address |
| `db` | `DASHBOARD_DB` | `./dashboard.db` | SQLite file |
| `public_url` | `DASHBOARD_PUBLIC_URL` | — | own origin (blocked in iframes); a path in it must equal `base_path` |
| `base_path` | `DASHBOARD_BASE_PATH` | `/` | sub-path behind a reverse proxy, e.g. `/panel/` (see [install.md](install.md), section C) |
| `title` | `DASHBOARD_TITLE` | `Go Dash` | toolbar title |
| `seed` | `DASHBOARD_SEED` | — | menu JSON imported when the menu is empty |
| `max_tabs` | `DASHBOARD_MAX_TABS` | `10` | open item tabs (LRU beyond it) |
| `login_rate` | `DASHBOARD_LOGIN_RATE` | `5` | admin login attempts per minute per IP (dashboard unlocks have their own counter with the same limit) |
| `default_theme` | `DASHBOARD_DEFAULT_THEME` | `ocean-light` | theme for analysts without a saved choice |
| `default_theme_style` | `DASHBOARD_DEFAULT_THEME_STYLE` | `flat` | `flat` or `3d` (No Flat) |
| `frame_src` | `DASHBOARD_FRAME_SRC` | `http: https:` | CSP `frame-src` |
| `iframe_sandbox` | `DASHBOARD_IFRAME_SANDBOX` | `allow-scripts allow-same-origin allow-forms allow-popups` | iframe sandbox |
| `tls_cert` / `tls_key` | `DASHBOARD_TLS_CERT` / `_KEY` | — | serve HTTPS directly |
| `cookie_secure` | `DASHBOARD_COOKIE_SECURE` | `false` | force Secure cookie |
| `trust_proxy` | `DASHBOARD_TRUST_PROXY` | `false` | trust `X-Forwarded-*` |
| `log_level` / `log_format` | `DASHBOARD_LOG_LEVEL` / `_FORMAT` | `info` / `text` | logging |
| `admin_password_hash` | `DASHBOARD_ADMIN_PASSWORD_HASH` | — | bcrypt hash (highest precedence) |
| `admin_password` | `DASHBOARD_ADMIN_PASSWORD` | — | plain password (hashed in memory) |

Without any password source the web administration is disabled (the CLI still works).

## Iframes and their limits

Many sites forbid being framed (`X-Frame-Options` / `frame-ancestors`), e.g.
GitHub or Google. For those, set the item target to **"New browser tab"**
(`blank`). Every iframe tab also has **"Open in new tab"** and **"Reload"**
buttons. The dashboard's own origin can never be opened in an iframe.

## Security

- CSP `script-src 'self'`, no inline scripts; `frame-ancestors 'self'`.
- Iframes sandboxed without `allow-top-navigation`/`allow-popups-to-escape-sandbox`.
- Admin: bcrypt, server-side sessions (2 h idle / 12 h absolute), CSRF token,
  `SameSite=Strict` cookie, 5 login attempts per minute per IP.
- Dashboard passwords: bcrypt, server-side viewer sessions scoped to one
  dashboard (never accepted as admin sessions), `Cache-Control: no-store` on
  protected menus, unlock rate limited per IP.
- Run behind HTTPS in production (`--tls-cert/--tls-key` or a proxy with
  `--trust-proxy --cookie-secure`).

## Backup and restore

```bash
go-dash backup -o /backups/dashboard-$(date +%F).db   # safe while serving (VACUUM INTO)
# restore: stop the service, replace dashboard.db, delete dashboard.db-wal/-shm, start
```

## Release artifacts

`make dist` writes release files to `dist/` (ignored by git), each with a
`.sha256`:

| File | Content |
| --- | --- |
| `go-dash-<version>-linux-amd64` | static binary (frontend embedded) |
| `go-dash-<version>-linux-amd64.tar.gz` | the binary as `go-dash`, `README.md`, `dashboard.toml.example` |
| `go-dash-image-<version>.tar.gz` | Docker image `ghcr.io/jniltinho/go-dash:<version>` and `:latest` |
| `go-dash-<version>-linux-amd64.tar.gz` | `make dist-server`: server package with configured `go-dash.env` and `Makefile` (`sudo make install`); see the [installation guide](install.md) |
| `docker-compose.yml`, `.env.example` | run the image without building it ([`deploy/docker-compose.yml`](../deploy/docker-compose.yml)) |

```bash
make dist                                   # or: make dist-bin / make dist-image
make dist-bin GOOS=linux GOARCH=arm64       # other platforms (binary only)
docker load -i dist/go-dash-image-<version>.tar.gz
```

Deploying the image on a server (copy the `dist/` image tarball, `docker-compose.yml`
and `.env.example`):

```bash
docker load -i go-dash-image-<version>.tar.gz
cp .env.example .env        # set DASHBOARD_ADMIN_PASSWORD (image and tag are preset)
docker compose up -d        # http://<server>:8080
```

### CI / Release

GitHub Actions in [`.github/workflows`](../.github/workflows):

| Workflow | Runs on | What it does |
| --- | --- | --- |
| `ci.yml` | push to `main`, pull requests, manual | frontend check, type-check, tests and build; `gofmt`, `go vet`, `go test`; static binary build |
| `release.yml` | tag `vX.Y.Z` | runs the CI, builds `go-dash-<tag>-linux-{amd64,arm64}.tar.gz` with `make dist-bin` and publishes a GitHub release (notes from `CHANGELOG.md`, `checksums.txt`) |
| `docker-image-publish.yml` | push to `main`, `v*` tags (build only on pull requests) | builds the image and pushes it to `ghcr.io/jniltinho/go-dash` (`main`, `X.Y.Z`, `X.Y`, `latest`) |

```bash
git tag v1.2.3 && git push origin v1.2.3     # release + image
docker pull ghcr.io/jniltinho/go-dash:<version>   # e.g. 1.2.3 (no "v") or latest
```

## Where data and settings live

| What | Where |
| --- | --- |
| Menu items (default card order), admin password set via CLI, sessions | SQLite: `/data/dashboard.db` in the `dashboard-data` Docker volume; `/opt/go-dash/data/dashboard.db` with the systemd service; `./dashboard.db` (or `--db`/`DASHBOARD_DB`) otherwise |
| Server settings (title, IP and port, default theme, password, TLS…) | `DASHBOARD_*` environment variables: `.env` with Docker Compose, `/opt/go-dash/go-dash.env` with the systemd service; or `dashboard.toml` (`--config`); never written by the app |
| Each analyst's theme, style and card order | their browser (`localStorage`) |

Back up the database with `go-dash backup` (see below and the
[installation guide](install.md) for systemd and Docker).
